## تنبيهات تحتاج متابعة

- حماية كلمات المرور المسرّبة معطّلة في إعدادات Supabase Auth. موصل Supabase المتاح لا يوفّر تعديل هذا الخيار؛ فعّله من **Authentication → Sign In / Providers → Password → Leaked password protection** قبل الإطلاق العام، مع توقع رفض كلمات المرور المعروفة بأنها مسرّبة عند تعيينها أو تغييرها.
- بقيت تحذيرات الدوال الخمس ذات `SECURITY DEFINER` المتاحة للمستخدم المسجل. تحقق فحص الصلاحيات من حجبها عن `anon`، ومن أن `has_role` و`owns_store_order` و`place_order` و`update_store_order_status` تعتمد `auth.uid()` أو تحقق ملكية/دورًا. `approve_store` يستدعي `has_role('admin')`. هذه صلاحيات لازمة للسياسات وتدفقات RPC الحالية؛ لا تُلغَ دون نقل الاعتماد واختبار سياسات RLS.
- بقيت تحذيرات تعدد سياسات السماح في عمليات قراءة وكتابة متعددة. السياسات تمثل مسارات منفصلة للمدير والمالك/البائع والعميل؛ دمجها يحتاج مراجعة منطق `OR` واختبارات أدوار قبل تغيير الإنتاج. لا تشير هذه التحذيرات وحدها إلى تجاوز RLS.
- فهارس المفاتيح الخارجية السبعة صارت موجودة. Advisor ما زال يذكر 18 فهرسًا غير مستخدم؛ معظمها يعود إلى غياب بيانات واستخدام إنتاجي بعد. لا تحذفها اعتمادًا على إحصاءات مشروع شبه فارغ.
- يوجد اختلاف بين تاريخ المخطط اليدوي وسجل migrations. لا تستخدم `supabase db push` قبل إصلاح سجل الأساس عبر `supabase migration repair` ومقارنة المخطط النهائي.
