# شامنا SHAMNA

سوق إلكتروني عربي متعدد المتاجر، مبني بـ React وTypeScript وVite، باتجاه RTL وتصميم متجاوب. يبدأ التركيز بقطنا وجرمانا. عند غياب إعداد Supabase يعرض الموقع منتجات توضيحية معلّمة بوضوح، ولا يسمح بطلبها.

## التشغيل

المتطلبات: Node.js 22.12 أو أحدث، وpnpm 11.25.0.

```sh
pnpm install
pnpm dev
```

للاتصال بـSupabase محليًا، انسخ `.env.example` إلى `.env.local` وأدخل رابط المشروع ومفتاح الواجهة العامة فقط. ملف `.env.local` مستثنى من Git. لا تضع مفتاح `service_role` أو أي مفتاح إداري في الواجهة.

```text
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
```

## ما يعمل في النسخة الحالية

- واجهة عربية RTL، بحث، تصفية حسب الفئة والمنطقة والمتجر، تفاصيل المنتج، وسلة محلية.
- تسجيل حساب ودخول وخروج بالبريد، الملف الشخصي، طلب إنشاء متجر، وإدارة المناطق والفئات والمتاجر والمنتجات والطلبات وسجل تدقيق مختصر حسب دور قاعدة البيانات.
- المحفوظات تبقى على الجهاز الحالي فقط، وعناوين التوصيل تُحفظ في حساب الزبون ويمكن إعادة استخدامها.
- عند ربط Supabase: تحميل الكتالوج من قاعدة البيانات، رفع صور المنتجات إلى Storage، إتمام الطلب بالدفع عند الاستلام، وإعادة التحقق من السعر والمخزون ورسوم التوصيل داخل قاعدة البيانات.
- لوحة الحساب تعرض وظائف الزبون والبائع والإدارة بحسب الأدوار الممنوحة من قاعدة البيانات. السياسات الفعلية تعتمد على RLS وإجراءات قاعدة البيانات.

## قاعدة Supabase الحالية

فُحص مخطط مشروع Supabase وسياسات RLS قراءةً فقط بتاريخ 2026-10-23. قاعدة البيانات تحتوي الجداول الأساسية للملفات الشخصية والأدوار والمدن والفئات والمتاجر والمنتجات والعناوين والطلبات وسجل التدقيق، مع تفعيل RLS. أعمدة المخزون وحالات المتجر تطابق ترحيل الأساس في `supabase/migrations/202610220001_initial_marketplace.sql`.

طبّقنا على المشروع ترحيلًا أمنيًا واحدًا محدودًا لإلغاء التنفيذ المباشر من `anon` و`authenticated` لدالتين تعملان فقط كمشغّلات قاعدة بيانات. تحقّقنا أن المشغّلين ما زالا موجودين وأن الصلاحيتين أُزيلتا. سجل Supabase يحتوي الآن هذا الترحيل فقط؛ سجل الترحيل الأساسي ما زال غير ممثل فيه لأن المخطط الأصلي أُنشئ من محرر SQL. لا تشغّل ترحيل الأساس على قاعدة المشروع الحالية، لأنه يحتوي أوامر إنشاء جداول وأنواع موجودة بالفعل. استخدم `supabase migration repair` لمزامنة سجل الترحيلات قبل أي نشر migrations مستقبلي.

توجد نسخة محلية أقدم وغير مطبقة من ترحيل المرحلة الثانية في `docs/archive/local-stage2/`؛ لا تنقلها إلى مجلد migrations. تفاصيل الفحص والتنبيهات المتبقية في `docs/SUPABASE_STATE.md`.

لم يُقرأ أي ملف `.env` ولم يُنشأ ملف `.env.local`، ولم نغيّر إعدادات البريد أو كلمات المرور أو الاستضافة.

## الفحوص

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

النشر إلى Netlify غير مفحوص في هذه المرحلة. إعداد البناء المتوقع هو `pnpm build` ومجلد النشر `dist` كما في `netlify.toml`. لا تنشر قبل إضافة متغيرات البيئة المطلوبة إلى إعدادات الاستضافة ومراجعة قائمة الإطلاق.

راجع `docs/DECISIONS.md` و`docs/RELEASE_CHECKLIST.md` و`docs/archive/local-stage2/` قبل متابعة النشر أو تغيير مخطط قاعدة البيانات.
